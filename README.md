# MARINE 360

نسخة تطوير محلية أُعدّت من أرشيف المشروع المرفق بتاريخ 30 أكتوبر 2026. لم يُعد تصميم واجهة الملاحة أو تغيير ملفات المسح والحسابات الملاحية الأساسية.

## التشغيل

ثبّت Node.js 24 مع npm، ثم افتح الطرفية داخل هذا المجلد:

```powershell
npm ci
npm run dev
```

افتح `http://127.0.0.1:8080/`. أدخل اسم السفينة وأكمل شاشة الموافقة الموجودة أصلًا. الخادم محلي افتراضيًا. عند الحاجة لاختباره عبر الشبكة استخدم `npm run dev -- --host 0.0.0.0` مع إعداد HTTPS مناسب لوظائف الأجهزة.

في عرض **Model** توجد ثلاثة أشرطة: المبالغة الرأسية للأعماق، و«حجم السفينة» لتغيير حجم المجسم من 0.25× إلى 4×، و«مستوى الأعماق» لرفع قاع المودل أو خفضه من ‎−50 إلى ‎+50 مترًا بالنسبة لسطح البحر. القيمة 1× تحافظ على حجم السفينة الأصلي، وإزاحة الأعماق 0 تحافظ على العرض الأصلي. إزاحة القاع للعرض فقط؛ السفينة وسطح البحر ثابتان، ولا تتغير بيانات المسح أو حسابات الملاحة.

زر **GTS** يفعّل متابعة السفينة: تبقى في منتصف العرض وتتحرك الخريطة مع كل تحديث للموقع من GPS أو JRC أو Bluetooth، مع الاحتفاظ بمستوى التكبير. يتحول الزر إلى اللون الذهبي أثناء المتابعة. اضغطه مرة أخرى لإيقافها، أو اسحب الخريطة لتصفحها بحرية؛ السحب يوقف متابعة العرض فقط ويُبقي مصدر الموقع متصلًا. اضغط **GTS** لاستئناف التمركز على أحدث موقع. الزر نفسه في لوحة السفينة يؤدي الوظيفة نفسها.

**Speed vector** يعرض من موقع السفينة الحي متجهًا أخضر لمدة **10 دقائق**: طوله = SOG بالعقدة × 10÷60 ميلًا بحريًا، واتجاهه COG. تظهر علامات كل دقيقة وعلامة أطول عند الدقيقة الخامسة؛ تُخفى العلامات المتقاربة عند التصغير. يعرض رأس السهم المدة والمسافة، ويظل طول المتجه الجغرافي مطابقًا للسرعة دون حد أدنى مصطنع. مثال: 12 عقدة تعطي 2 NM. يتحدث من GPS أو RMC/VTG عبر JRC وBluetooth، ولا يستبدل COG بزاوية مقدمة السفينة HDG. يختفي عند سرعة صفر أو نقص البيانات، أو بعد 15 ثانية دون موقع وحركة حديثين، وعند فصل المصدر. يمكن إظهاره وإخفاؤه من **Route monitoring** أو **setting**، وتبقى مدته 10 دقائق مستقلة عن إعداد COURSE LINE. شكل متجه السرعة وعلامات الزمن مستلهم من [دليل Furuno FMD3xxx، قسم Velocity Vectors](https://furunousa.com/-/media/sites/furuno/document_library/documents/manuals/public_manuals/fmd3xxx_operators_manual.pdf).

من قائمة **setting** عدّل حجم السفينة على الخريطة والنموذج، ولون خط **Past track** وسُمكه ووضوحه وعدد نقاطه المعروضة. ويمكن ضبط وضوح طبقات الأعماق وإظهار خط الاتجاه وطوله بالدقائق. تسري التغييرات فورًا وتُحفظ على الجهاز، وتتزامن مع أدوات **Route monitoring** وشريط النموذج. زر **استعادة الإعدادات الافتراضية** يعيد قيم العرض الأصلية. تغيير طول السجل المعروض لا يمسح النقاط المسجلة ضمن حد السجل الحالي البالغ 8000 نقطة. يُسجل المسار من GPS وJRC وBluetooth.

من **Windows / النوافذ** فعّل **«ساعة بحرية»** لعرض ساعة عقارب مع توقيت البصرة وUTC والتاريخ. تتحدث كل ثانية اعتمادًا على ساعة الجهاز، ويمكن سحبها من شريط العنوان وإغلاقها أو إظهارها من اختصار الساعة في الأدوات الجانبية.

## أوامر التطوير

| الأمر | الغرض |
|---|---|
| `npm run dev` | تشغيل التطوير والتحديث المباشر |
| `npm run typecheck` | فحص TypeScript |
| `npm run lint` | فحص الشيفرة؛ يوجد تحذير قديم موثّق في تقرير الفحص |
| `npm test` | اختبارات المشروع واختبارات الملاحة، دون إرسال تنبيهات خارجية |
| `npm run test:navigation` | اختبارات الحسابات وNMEA وAIS وبيانات المسح والمدّ |
| `npm run build` | إنشاء نسخة إنتاج، دون تشغيل ترحيلات قاعدة البيانات |
| `npm run build:render` | بناء خادم Node.js مستقل لـRender داخل `.output/` |
| `npm start` | تشغيل خادم Render بعد بنائه، مع قراءة إعدادات التطبيق المحلية أو الخادمية |
| `npm run preview` | عرض البناء على `http://127.0.0.1:8081/` |
| `npm run test:ui` | اختبار الواجهة على خادم التطوير المشغّل مسبقًا |
| `npm run test:ui -- http://127.0.0.1:8081/` | اختبار واجهة البناء المشغّل مسبقًا |
| `npm run check` | فحص الأنواع وlint والاختبارات والبناء |
| `npm run build:deploy` | بناء ثم ترحيلات قاعدة البيانات عند إعدادها عمدًا |

اختبار الواجهة يستخدم Microsoft Edge المثبّت على Windows. في الأنظمة الأخرى شغّل `npx playwright install chromium` مرة واحدة. يمكن تحديد متصفح آخر عبر `BROWSER_CHANNEL`. تُحفظ النتائج والصور في `test-results/navigation/`. بعض اختبارات القالب تُنشئ روابط مجلدات؛ قد تمنعها بيئة عزل صارمة، ويجب عندها تشغيلها في طرفية محلية عادية.

## الإعدادات

أضيف **Network UDP** في **Sensors & connections** لربط R5 SUPREME عبر UDP عادي أو Multicast/IEC 61162-450. يدعم IP المصدر وPort واختيار بطاقة الشبكة، واكتشاف المرسل دون تحريك السفينة حتى اختياره، والتشخيص وقراءة NMEA وبيانات الموقع والسرعة. تعمل خدمة محلية تلقائيًا في التشغيل المحلي، ويمكن تشغيلها يدويًا عبر `npm run network:bridge`. راجع [دليل ربط R5 وUDP وإعداد جدار الحماية](docs/NETWORK_UDP_AR.md) لمطابقة إعدادات الجهاز والشبكة.

وضع المصادقة الأصلي متوقف كما في `.grok/app-env.json`، ولا تلزم قاعدة بيانات لواجهة الملاحة الحالية. أبقيت وحدات المصادقة والربط السابقة دون تفعيل حسابات أو خدمات جديدة.

تنبيهات المرساة المرئية والصوتية موجودة. لتنبيهات Telegram ضع قيمك في `.env.local`:

```dotenv
TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_CHAT_ID=your_chat_id
```

في مجلد التطوير المحلي احتُفظ بالقيم السابقة في `.env.local` للمحافظة على الإعداد الحالي. الملف مستثنى من Git ومن حزمة ZIP. الحزمة القابلة للمشاركة تحتوي `.env.example` فقط؛ انسخه إلى `.env.local` واضبط القيم لتفعيل إرسال Telegram. أعد تشغيل الخادم بعد التعديل. لا تستخدم بادئة `VITE_` للأسرار. في الاستضافة اضبط القيم كمتغيرات بيئة خادمية.

كان مفتاح Telegram موجودًا في المصدر الأصلي؛ يُنصح باستبداله من إعدادات البوت وتحديث القيمة المحلية. لم يُستخدم المفتاح لإرسال رسائل أثناء الفحص.

الأرشيف الأصلي لم يُعدّل. الملفات التاريخية، والمرفقات، ونسخ THIQAR المتداخلة، ومخرجات البناء القديمة لم تُخلط مع مصدر التطوير. مراجع Grok اللازمة لاختبارات القالب محفوظة تحت `tests/fixtures/upstream/` كبيانات اختبار، وليست تعليمات تشغيل لهذا المشروع.

إعداد مصادقة Grok التجريبي الموروث، إذا لزم تفعيله مستقبلًا، يقرأ `GROK_PREVIEW_CLIENT_SECRET` من البيئة الخادمية. لا توجد قيمته داخل الشيفرة؛ المصادقة تبقى متوقفة افتراضيًا.

## النشر على Render

اختر **Web Service** وخطة **Free**، والمستودع `ckpb4fjvs7-ops/marine` والفرع `main`. اترك Root Directory فارغًا، واضبط Build Command على `npm ci && npm run build:render` وStart Command على `npm start`. يوجد `render.yaml` بالإعدادات نفسها للاستخدام مع Blueprints. المشروع يحدد Node.js 24 عبر `.nvmrc` و`engines`.

اضبط `NITRO_HOST=0.0.0.0`، واترك Render يحدد `PORT` تلقائيًا. اضبط `VITE_AUTH_ENABLED=false` للاحتفاظ بوضع الملاحة الحالي. مفاتيح Telegram اختيارية وتوضع في Environment Variables على الخادم. لا تلزم قاعدة بيانات للوظائف الحالية.

البناء العادي `npm run build` يبقي إعداد Vercel متاحًا. البناء `build:render` ينتج `.output/server/index.mjs` وموارد الموقع في `.output/public/`. شغّل خادم Node كاملًا حتى تعمل وظائف AIS والمدّ وNAVTEX والتنبيهات الخادمية.

خطة Render المجانية تتوقف بعد 15 دقيقة بلا زيارات، وقد تحتاج نحو دقيقة للاستيقاظ؛ هذا النشر مخصص للتجربة. [حدود الخطة الرسمية](https://render.com/docs/free).
