# ربط R5 SUPREME عبر Network UDP

افتح **Sensors & connections → Network UDP**. يستقبل التطبيق بيانات NMEA من الجهاز على الكمبيوتر المحلي، ثم يحدّث موقع السفينة وSOG وCOG والاتجاه وPast track وSpeed vector وGTS. استقبال UDP يعمل بخدمة Node محلية؛ فتح صفحة ويب على استضافة بعيدة لا يجعل خادم الاستضافة متصلًا بشبكة السفينة.

## إعداد الجهاز والشبكة

1. صِل كمبيوتر التطبيق بشبكة Ethernet الخاصة بجهاز R5/Navigation Sensor. اختر بطاقة تلك الشبكة من القائمة، خصوصًا إذا كان الإنترنت يعمل على Wi-Fi أو توجد VPN. عنوان IP الجهاز غير ظاهر في الصورة المرفقة؛ اقرأه من إعدادات Network/Ethernet أو استخدم الاكتشاف أدناه. قد يختلف عنوان شاشة CDU عن عنوان Navigation Sensor المرسل الفعلي.
2. تأكد من توافق IP وقناع الشبكة بين الكمبيوتر والجهاز. لا تغيّر عنوان بطاقة شبكة السفينة دون معرفة الإعداد الحالي. يعرض **تحديث بطاقات الشبكة** عناوين الكمبيوتر المتاحة فعليًا.
3. فعّل خرج NMEA/Ethernet في R5. اختر **RMC** للموقع والسرعة وCOG، أو **GGA/GLL** للموقع مع **VTG** للسرعة والاتجاه، بمعدل مثل 1 Hz. يُستخدم HDT/THS إذا كان مصدر اتجاه حقيقي متاحًا. العمق DPT/DBT/DBS/DBK يُقرأ إن أرسله مصدر NMEA/Gateway؛ جهاز GNSS وحده ليس حساس أعماق.
4. للاستقبال البحري Multicast اختر إعداد **R5 / NAVD**: المجموعة `239.192.0.4` والمنفذ `60004`. هذا إعداد مجموعة NAVD القياسي، وليس تخمينًا لعنوان جهازك. طابقهما مع إعداد الجهاز الفعلي إذا جرى تخصيصه. يدعم المستقبِل إطار `UdPbC` وTAG blocks والجمل المتعددة في الحزمة.
5. إذا كان جهازك مضبوطًا على UDP عادي اختر **Unicast / Broadcast**. وجّه الإرسال من الجهاز إلى IP الكمبيوتر أو عنوان البث المناسب. **UDP Port في التطبيق هو منفذ استقبال الكمبيوتر**، وليس بالضرورة منفذ المصدر الذي ترسل منه الوحدة.
6. اكتب **IP الجهاز المرسل** واضغط **Connect UDP**. يقبل التطبيق الملاحة من ذلك المصدر فقط. لا توجد أوامر تحكم أو تغيير إعدادات تُرسل إلى الجهاز من هذا المستقبل.

يمكن ترك IP المصدر فارغًا والضغط على **اكتشاف مصدر UDP**؛ تُعرض عناوين المرسلين وعدد الحزم دون تحريك السفينة. اضغط عنوان المرسل الصحيح لتطبيق بياناته. يُسمح بمصدر ملاحة واحد في الوقت نفسه؛ الاتصال بمصدر UDP محدد يفصل GPS/COM/Bluetooth السابق، والاكتشاف السلبي وحده لا يفصله.

## الخدمة المحلية

في التشغيل المحلي على `127.0.0.1:8080` تبدأ الخدمة تلقائيًا عند الاتصال أو تحديث البطاقات. واجهة التحكم تستمع على `127.0.0.1:8092` فقط، بينما منفذ UDP يستقبل على بطاقة الشبكة المختارة. تُحفظ إعدادات الاتصال على الجهاز؛ لا يُعاد الاتصال بمصدر الملاحة تلقائيًا بعد إعادة فتح الصفحة.

للتشغيل اليدوي من مجلد المشروع، مع Node.js 24:

```powershell
npm run network:bridge
```

أو:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-network-udp.ps1
```

إذا كان منفذ الخدمة HTTP `8092` مستخدمًا، شغّلها بمنفذ آخر، ثم عدّل **عنوان خدمة UDP** في الإعدادات المتقدمة. هذا لا يغيّر منفذ UDP الخاص بالجهاز:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-network-udp.ps1 -Port 8093
```

عند استخدام [الموقع المنشور على Render](https://marine360.onrender.com/)، شغّل الخدمة على الكمبيوتر المتصل بالجهاز ومرّر أصل الموقع المحدد، واسمح بالوصول للشبكة المحلية إذا طلب المتصفح ذلك:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-network-udp.ps1 -AllowOrigin https://marine360.onrender.com
```

لا تعمل هذه الخدمة على كمبيوتر آخر لمجرد فتح الموقع على الهاتف؛ يلزم تشغيل المستقبل على الكمبيوتر المتصل فعليًا بشبكة الجهاز. واجهة التحكم مقيدة بـloopback وبالأصول المسموح بها، ولا تُفتح منفذ تحكم عام على الشبكة. ينتهي الاستقبال بعد 15 ثانية دون أي تبويب متصل، ويمكن فصله فورًا بزر **Disconnect UDP**. التبويب الآخر لا يستطيع فصل جلسة لا يملكها.

## جدار الحماية

إذا ظهرت حزم صفر رغم صحة إعداد الجهاز والكابل وبطاقة الشبكة، اسمح لبرنامج Node باستقبال UDP. يوجد سكربت لقاعدة Windows ضيقة النطاق: منفذ UDP المحدد، وIP المرسل المحدد، ومسار Node فقط. لم تُضف قاعدة جدار حماية تلقائيًا ضمن هذا التعديل.

شغّل PowerShell كمسؤول، واستبدل عنوان المثال بعنوان R5 الحقيقي:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/allow-network-udp.ps1 -Port 60004 -SourceIp 192.168.1.10
```

## قراءة التشخيص

- **المنفذ مفتوح**: نجح فتح socket؛ لا يعني وحده وصول بيانات R5.
- **حزم/بايت تتزايد**: UDP يصل إلى الكمبيوتر. تعرض القائمة عناوين المرسلين الفعلية.
- **مصادر مستبعدة**: الحزم قادمة من IP مختلف عن الفلتر؛ اختر المرسل الصحيح من القائمة.
- **NMEA يتزايد**: استُخرجت جمل صالحة بنيويًا وchecksum عند تفعيله. يعرض السطر الأخير نوع الرسالة لتشخيص الخرج.
- **مواقع صالحة / موقع حي عبر UDP**: وصلت جمل GNSS صالحة حديثًا. إن كان الموقع خارج منطقة المشروع بأكثر من الحد الموجود سابقًا، يعرض التطبيق سبب تجاهله.
- **checksum مرفوض**: وصلت جمل تالفة أو تنسيق غير مناسب. أبقِ التحقق مفعّلًا لجهاز R5؛ تعطيله مخصص لمرسل قديم معروف يرسل دون checksum، وليس لعلاج بيانات تالفة.
- **منفذ مستخدم**: يوجد مستمع آخر. افصله أو طابق إعداد الإرسال مع منفذ آخر دون تغيير خدمة كانت تعمل على السفينة.
- **بيانات وصلت دون موقع**: فعّل RMC أو GGA/GLL. جمل HDT وحدها لا تحتوي موقعًا؛ GGA وحدها لا تكفي لـSpeed vector دون SOG وCOG.

الاختبارات البرمجية تستقبل حزم UDP وMulticast فعلية عبر loopback، وتتحقق من UdPbC وTAG وchecksum وتصفية المصدر وبث المتصفح وGTS وSpeed vector. تبقى مطابقة إعدادات جهاز R5 والكابل والسويتش وجدار الحماية بحاجة إلى تجربة حزم حقيقية من الجهاز نفسه.

## المراجع

يدعم R5 SUPREME NAV شبكة LWE/IEC 61162-450 وفق [ورقة Saab الرسمية](https://www.saab.com/globalassets/products/surveillance/r5-supreme-nav-mkii/r5_supreme_nav_mkii.pdf). مجموعة NAVD وعنوانها ومنفذها وأنواع الإطارات موضحة في [دليل Anschütz Synapsis، قسم IEC 61162-450](https://www.anschuetz.com/fileadmin/user_upload/Anschuetz/Approvals/operation_manuals/synapsis_system_manual/10000000964_SYNAPSIS_System_Manual_05.03.xx.pdf). دليل Saab الأصلي لتكوين مخارج NMEA والشبكة متاح في [R5 Navigation System manual](https://ressource.profmarine.fr/gps/notice-GPS-R5.pdf).
