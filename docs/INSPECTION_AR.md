# تقرير فحص وتجهيز MARINE 360

تاريخ الفحص: 30 أكتوبر 2026. المصدر: `4yT56ZjGLIc3iiiE-grok-workspace.zip`.

## النتيجة

أُعدّت نسخة تطوير قابلة للتثبيت والتشغيل والبناء على Windows باستخدام Node.js 24 وnpm، مع اختبارات ووثائق تشغيل. بقي الأرشيف الأصلي دون تعديل. اجتاز الأمر المجمع `npm run check` الفحص النهائي برمز خروج 0.

المقارنة ببصمات SHA-256 تثبت بقاء جميع ملفات المسح والأصول العامة والحسابات الملاحية الأساسية دون تعديل. سجل المقارنة يغطي 113 ملفًا أصليًا من التطبيق وإعداداته، منها 97 ملفًا مطابقًا للأصل. الاختلافات الستة عشر تشمل التجهيز، والمصادقة الموروثة، وتنبيه Telegram، وتعليقات فحص الشيفرة، واختبارات القالب، وملفات الحزم، وإضافة شريطي حجم السفينة ومستوى الأعماق المطلوبين لاحقًا في `survey-explorer.tsx`.

## تحديث مستوى الأعماق

أُضيف شريط ثالث لرفع قاع المودل وخفضه بالنسبة لسطح البحر من ‎−50 إلى ‎+50 مترًا بخطوة نصف متر، وقيمة افتراضية 0. يغير موضع مجسم القاع فقط؛ تبقى السفينة وسطح البحر ثابتين، ولا تتغير نقاط المسح أو قراءة الأعماق الملاحية. تتبع الإزاحة مقياس المبالغة الرأسية، وتستمر عند تبديل المسح أو العرض. وُسّعت المساحة القصوى لتذييل المودل حتى تظهر الأشرطة الثلاثة على الهاتف.

تحقق الفحص في مشهد Three.js الفعلي من تحرك القاع في الاتجاهين وثبات موضع السفينة وحجمها وسطح البحر، وعدم تغير إحداثيات رؤوس شبكة المسح. نجحت هذه الفحوص، بما فيها تبديل المسح والمبالغة الرأسية وقابلية استخدام الأشرطة الثلاثة دون حجب زر الإنذار، على الحاسوب والهاتف. نجح TypeScript والبناء، مع بقاء تحذير lint السابق فقط.

## إضافة الساعة البحرية

أُضيف خيار «ساعة بحرية» ضمن Windows، مع اختصار في الأدوات الجانبية. تعرض نافذة قابلة للسحب والإغلاق ساعة عقارب بتوقيت البصرة، ووقتين رقميين للبصرة وUTC، وتاريخ كل منهما. مصدر الوقت ساعة الجهاز، مع تحديث كل ثانية أثناء ظهور النافذة وتنظيف المؤقت عند إخفائها. تدعم ألوان الوضع النهاري والليلي والعرضين Chart وModel.

نجح اختبار التوقيت باستخدام وقت جهاز مضبوط على UTC مع منطقة متصفح مختلفة، بما يشمل اختلاف تاريخ البصرة وUTC عند منتصف الليل وتحديث الثواني. نجحت الإضافة والإخفاء من القائمة والاختصار، والإغلاق وإعادة الفتح، والسحب والبقاء ضمن حدود الشاشة على الحاسوب والهاتف. نجح TypeScript والبناء، مع بقاء تحذير lint السابق فقط. صور الساعة محفوظة تحت `docs/qa/marine-clock-desktop.png` و`marine-clock-mobile.png`.

## تحديث حجم السفينة

أُضيف شريط ثانٍ أسفل المبالغة الرأسية في عرض Model، لتغيير حجم مجسم السفينة من 0.25× إلى 4×، بقيمة افتراضية 1× تحافظ على الحجم السابق. يؤثر الشريط في مقياس المجسم فقط، وتُحفظ قيمته أثناء تبديل العرض وتحديث موقع السفينة، دون تغيير الأعماق أو الإحداثيات أو حسابات الملاحة. وُضعت مساحة على يمين الشريطين حتى لا يحجبهما زر الإنذار على الهاتف.

نجح فحص TypeScript والبناء، وكذلك فحص الحدين الأدنى والأقصى واستقلال الشريطين والتبديل بين العروض وعدم حجب الشريط على مقاسي الحاسوب والهاتف. أُعيد اختبار سيناريوهات واجهة الملاحة الحالية بنجاح.

## التعديلات المنفذة

1. فصل مصدر التطوير عن المرفقات ونسخ THIQAR ومخرجات البناء القديمة، مع الاحتفاظ بمراجع القالب اللازمة للاختبارات كبيانات في `tests/fixtures/upstream/`. تعليمات Grok داخل الأرشيف ليست طلبات من المستخدم ولم تُنفذ كتعليمات لهذه المهمة.
2. إصلاح تشغيل Vite على Windows باستدعاء مدخل JavaScript عبر Node بدل تشغيل shim للأوامر. لا يتغير سلوك إعداد علم المصادقة الأصلي.
3. إضافة `.env.local` لإعدادات Telegram الخادمية وإزالة القيم الثابتة من المصدر. احتُفظ بالإعداد السابق محليًا، واستُثني من Git وZIP. عند غياب الإعدادات يُتجاوز الإرسال وتبقى الإنذارات المحلية. لم تُرسل رسائل Telegram أثناء التجهيز.
4. فصل البناء العادي عن ترحيلات قاعدة البيانات؛ أصبحت الترحيلات خطوة صريحة عبر `db:migrate` أو `build:deploy`.
5. تحديث Better Auth إلى 1.7.14 وZod إلى 4.6.7 وSeroval إلى 1.7.5، وتحديث ملف القفل. انخفضت تنبيهات `npm audit` من خمسة إلى صفر وقت الفحص. تم تكييف استدعاءات المصادقة الموروثة مع API الجديدة دون تفعيل تسجيل الدخول.
6. إصلاح خطأي lint دون تغيير سلوك الواجهة، وتجهيز اختبارات القالب للعمل من مجلدات مؤقتة محلية ومع روابط مجلدات Windows، وعزل اختبارات هوية المشاركة عن اسم التطبيق الفعلي.
7. إضافة تسع حالات لاختبارات الملاحة، واختبار واجهة قابل لإعادة التشغيل، ودليل تشغيل وبنية وقائمة فحص ميداني وملف بصمات المصدر.

## التحقق

| الفحص | النتيجة |
|---|---|
| TypeScript | ناجح |
| ESLint | صفر أخطاء، وتحذير قديم واحد |
| اختبارات Node | 265 ناجحة، صفر فاشلة، صفر متجاوزة |
| البناء | ناجح، مع تحذيرات موروثة من حزم الحركة بشأن `use client` |
| فحص الاعتماديات | صفر تنبيهات مسجلة عند الفحص |
| واجهة التطوير | ناجحة على 1440×1000 و390×844 |
| واجهة البناء | ناجحة على المقاسين نفسيهما |
| أخطاء JavaScript غير المعالجة | صفر أثناء سيناريوهات الواجهة |

حالات الملاحة المضافة تغطي RMC/GGA/GLL/VTG/HDT/THS/HDG، checksum، الاتجاهات والوحدات ومرجع جهاز الأعماق، المسافات وموضع جهة الانحراف، بيانات المسح الفعلية وحماية الأعماق المقاسة، دمج AIS، وأوقات المدّ وفق بغداد.

اختبار الواجهة يغطي البدء، الخريطة والمجسم والعرض المشترك، مدخل النهر، طبقات الأعماق والعلامات واتجاه الخريطة، إدخال الموقع، إنشاء مسار من نقطتين ومسحه، VRM/EBL والأثر وخط الاتجاه، وجود أدوات الأجهزة واختيار baud، ونافذة الملاحة والثيم. توجد صور ونتائج في [مجلد التحقق](qa/verification.txt).

## نقاط متابعة محددة

- التحذير الوحيد في effect تحديث الطقس داخل `survey-explorer.tsx` يتعلق باعتماد `hit`. أبقي الكود الأصلي دون إعادة جدولة تحديثاته ضمن مهمة التجهيز.
- ملف الواجهة الرئيسي كبير؛ يُفضّل تقسيمه تدريجيًا مع الاختبارات الحالية، لا إعادة كتابته دفعة واحدة.
- بعض طلبات المصادر الخادمية لا تضع مهلة تطبيق صريحة، وبعض المصادر تعتمد قراءة HTML أو واجهات الموردين الحالية؛ تحتاج اختبارات عقود ومتابعة عند تغيرها.
- وحدات المصادقة وApp Data موروثة من Grok، والمصادقة متوقفة أصلًا. تفعيلها مستقبلًا يحتاج إعدادًا مستقلًا ومسارات backend ومراجعة callback URLs الجديدة. لم يُختبر OAuth فعلي مع حسابات خارجية.
- مفتاح Telegram كان ضمن المصدر المرفق؛ استبداله وتحديث `.env.local` يعالجان استمرار استخدام مفتاح سبق تضمينه في أرشيف.
- اختبارات واجهة الهاتف تحاكي حجم الشاشة، ولا تثبت دعم الأجهزة على هاتف فعلي. لم تُفتح منافذ Serial أو BLE ولم تُختبر أذونات GPS أو دقة مصادر الملاحة الحية. راجع [قائمة الفحص الميداني](MANUAL_QA_AR.md).

## ملفات التسليم

المجلد `MARINE360` هو نسخة العمل المحلية مع الاعتماديات المثبتة. الحزمة `MARINE360-development.zip` تحتوي المصدر والاختبارات والوثائق وصور التحقق، وتستثني الاعتماديات ومخرجات البناء والملفات المؤقتة و`.env.local`. لتشغيل الحزمة بعد فكها: `npm ci` ثم `npm run dev`، مع ضبط Telegram إذا كان مطلوبًا.

## تجهيز GitHub

فُصل مفتاح عميل Grok التجريبي الموروث عن المصدر إلى `GROK_PREVIEW_CLIENT_SECRET` في البيئة الخادمية؛ احتُفظ بالإعداد المحلي داخل `.env.local` المستثنى من Git. المصادقة غير مفعّلة أصلًا، ولا تتغير وظائف الملاحة. فحص المصدر المخصص للرفع لم يجد مفاتيح Telegram أو GitHub أو مفاتيح خاصة أو قيم اعتماد ثابتة وفق أنماط الفحص. استُبعدت الاعتماديات ومخرجات البناء والملفات المؤقتة والإعدادات السرية من التتبع.
